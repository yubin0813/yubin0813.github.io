# 我写了 13 条奖励，它找到了第 14 条

> 一句话：机器人学会了躲到对手背后——因为我的记分表上，躲背后是最优解。

---

**[视频位：15 秒回放。面对面却不打，一个绕到另一个背后——待补]**

我训练了两台人形机器人打拳击。

看回放时，它们没在打——其中一个绕到了另一个的背后，正对着它，一动不动。

两个人就这样转了 60 秒，比分 0:0。

不是它们不会打拳。是我写的记分表告诉它：**躲在这里，比分最高。**

---

## 我的记分表

先交代背景：机器人拳击赛里，机器人做什么不靠指令，靠的是一份奖励函数——每一步仿真，系统按这份表给行为打分，强化学习算法想尽办法把总分刷到最高。我照着官方配置写了 13 条奖励，每一行都是我以为的"好拳击手该有的样子"。

把这 13 行摆出来，再加一列"躲到对手背后时能拿多少"：

| 奖励项 | 权重 | 作用 | 躲到对手背后时 |
|---|---|---|---|
| `facing` | 1.2 | 面朝对手 | **满分**（我在你背后，我仍看着你）|
| `defensive` | -8.0 | 被打扣分 | **完全避开**（你看不到我，打不到我）|
| `strike` | 0.3 | 推挤对抗 | 还能推 |
| `offensive_hit` | 50 | 打中得分 | 0 |
| `active_hit_shaping` | 1.5 | 手靠近对手 | 少许 |
| `vel` | 0.5 | 朝对手前进 | 少许 |
| `terminate` | 0.3 | 摔倒 | 0 |
| `complete_punch` | 0.05 | 完整出拳 | 0 |
| `action_rate` / `energy` / `foot_slip` | 官方原值 | 省力、别抖 | **都拿满**（不动最省）|
| `mutual_facing` | 不存在 | 对手是否看着我 | — |
| `stall` | **不存在** | 长时间不打就罚 | — |

数一遍：表上有 11 项，躲背后能拿满 9 项；唯一拿不到的是"打中"——

而我**没写**"不打就罚"。

## 为什么它是最优解

事后分析，这三条设计缺陷叠在一起，把"躲背后"推成了全局最优。

### ① 朝向奖励是个单边指标

```python
tar_dir_local = quat_apply_inverse(ego_root_quat, tar_dir_3d)
rew = torch.exp(-(1 - tar_dir_local[:, 0]) / sigma)   # sigma=0.5
```

它只检查"我是否看着你"，不检查"你是否看着我"。

站在背后，`tar_dir_local[0]` 依然接近 1 → 满分。

### ② 防守惩罚把"躲"变成了最高收益

```python
"defensive_hit_penalty_punch", -8.0
```

每挨一次有效命中扣 0.16 分，而"躲背后"可以把它压到 **0**。

在 3000 步的一局里，这是一笔很大的稳定收益。

### ③ 没有"必须进攻"的约束

官方 13 项里，所有进攻项都是**事件型**（打到才有分）。

```
不打 = 0 分，但不扣分
```

于是每个决策点的账目是这样的：

```
站着不动： 朝向满分 + 不挨打 + 省力 = 正收益
主动进攻： 有收益，但可能挨打 = 风险
```

**风险厌恶的策略必然选前者。**

## 数据：让判断可被验证

"它在躲"不能只靠回放的感觉，得能复算。我用两人前向向量的夹角余弦来度量：

```python
# 两人前向向量夹角的余弦
a = rotate([1,0,0], quat_A)
b = rotate([1,0,0], quat_B)
cos = dot(a, b)

cos ≈ -1  → 面对面
cos ≈ +1  → 同向（一个在另一个背后）
```

对整局录像统计：

| | 占比 |
|---|---|
| 面对面（cos < -0.5）| **17%** |
| 同向（cos > +0.5）| **74%** |
| 平均 cos | **+0.54** |

**[图位 1：朝向余弦的时间曲线——待补]**

**[图位 2：两人距离的时间曲线——待补]**

距离数据同样说明问题：中位距离 **0.51 m**，最近 **0.16 m**，一局接触 **453 次**——它们贴得足够近，甚至一直在发生碰撞（冲量 P50 0.20、P90 0.41，碰得很轻，但很频繁），只是 74% 的时间保持着"一个在另一个背后"的同向姿态。

比分 0:0，不是没交手，是从来没正面交手。

## 修法

加一项 stall：超过 2 秒没有有效命中就扣分，越久罚越重。

```python
t = torch.where(hit, 0, t + dt)          # 打中就清零
trigger = t >= interval_s
factor = torch.clamp(2.0 ** n, max=3.0)  # 第1次×1，第2次×2，第3次起×3
reward = -amount * factor * trigger
```

两个设计细节值得单说：

| 细节 | 原因 |
|---|---|
| `interval_s = 2.0`（不是 5）| γ=0.99 在 50Hz 下视野只有 **2 秒**；5 秒的惩罚只能拿到 8% 权重，等于没写 |
| 渐进倍率 | 第一次轻罚，防止偶然；持续不打才重罚 |

修完重新训练，三个数字的变化：

| | 修复前 | 修复后 |
|---|---|---|
| `stall` | 无 | -0.08 → **-0.0144**（收敛）|
| `hit` | 0 | **0.00366** |
| `task_reward` | -0.001 | **+0.127** |

机器人开始正面接战了。

## 附录：它能钻空子的四个工程原因

复盘时发现的四个坑，按"读者最可能踩到"排序。如果你也在做类似的多智能体对抗训练，大概率会在其中一两个上翻车。

### ① 传感器名字骗人

```
contact_sensor_A_torso  →  实际是"别人打 A 的躯干"
```

我们曾经读反，结果是**奖励它挨打**。

### ② 想奖励打头，那一项永远是 0

```python
rigid_body = body_weldid[geom_bodyid]   # 头部 geom 的 weldid = 躯干
mask = (rigid_body == head_link)        # 永远匹配不到
```

`head_link` 是无关节固定子体，weldid 指向躯干。

**后果：头部命中一直算在躯干通道里，我加的那 150 权重是死的。**

### ③ 冲量高估 4 倍

```python
# 错：单子步的力 × 20ms
impulse = force_norm * 0.02

# 对：20ms 内 4 个子步积分
impulse = sum(force_norm[-4:]) * 0.005
```

**62 N 的轻碰就能拿满分 → "打得重"从来没被奖励过。**

### ④ 距离门把出拳奖励乘没了

```
min_dist 0.5 / max_dist 1.0 / scale 0.05
在 1.5 米处系数 ≈ 3e-7
```

**出拳了，但奖励被乘成 0。**

## 最后

> 奖励函数不是说明书，是一个**可以被求解的优化问题**。
> 你写下的每一条，都是在给某个行为定价；
> 你没写的那一条，它自己会补上。
