# SLAM 建图如何实现：从一堵墙到整张地图的完整旅程

> 机器人走一圈就能画出一张地图。表面近乎魔法，背后是一条环环相扣的推理链。

## 一、SLAM 到底是什么，为什么重要

SLAM 是 Simultaneous Localization and Mapping 的缩写，中文为同步定位与地图构建。

名称中的“同时”是关键。机器人在移动时，要同时回答“我现在在哪”（定位）与“这地方长什么样”（建图）。两者无法拆开：定位需要地图作为参考，建图需要知道每一帧传感器数据来自哪个位置。这是 SLAM 的核心矛盾：**两个问题互相依赖，必须同时求解。**

难度可以从一个具体场景理解：一台搭载激光雷达的移动小车，在未到过的房间内自由行走，最终输出一张精确的室内地图。过程看似简单，机器人每一帧都要面对三个未知量——自身位置的变化量、环境的真实几何形状、传感器读数中的噪声。

SLAM 的价值不止于画地图。扫地机器人依靠它识别房间、规划路径；自动驾驶依靠它识别周围物体、确定车道内的位置；AR 设备依靠它在真实环境中叠加虚拟物体；无人机搜救、仓库 AGV、矿山勘探，底层都在运行 SLAM。**凡是有移动设备需要知道“我在哪、周围是什么”，就需要 SLAM。**

本文不覆盖所有算法分支，只把主流 SLAM 建图的完整流程走一遍，重点说明它如何处理让地图变歪、变糊、变形的几类问题。

## 二、系统结构：SLAM 由哪些模块组成

典型的视觉或激光 SLAM 系统，内部通常包含五个模块，彼此衔接：

```
传感器读数 → 前端(帧间对齐) → 优化器 → 地图维护 → 回环检测 → 优化器(再次)
                ↑                                              ↓
              里程计输出                                    最终地图
```

- **传感器**：激光雷达（2D/3D LiDAR）、相机（单目/双目/RGB-D）、IMU、轮式里程计，至少两种组合。
- **前端**：读取连续两帧数据，计算机器人在这两帧之间的移动量。每帧都必须执行的实时环节。
- **优化器**：收集一段时间内前端给出的相对位姿，统一做全局优化，使所有帧的位置关系最合理。
- **地图维护**：把传感器观测到的环境特征（点、线段、面、物体）转化为地图地标，建立“某帧看到了某个地标”的关联。
- **回环检测**：判断机器人当前看到的是否为此前到过的位置。若是，触发一次大规模优化，将累积漂移整体拉回。

后续章节围绕这五个模块展开。

## 三、前端：每一帧都在估计自身运动

前端是 SLAM 中频率最高的部分。传感器逐帧输出数据，前端逐帧计算相对运动。激光 SLAM 与视觉 SLAM 的实现路径不同，核心思路一致：**找到前一帧与当前帧之间的同名对应物，估计其位移。**

### 3.1 激光 SLAM 的前端匹配

激光雷达扫描出一圈点云，代表激光束击中障碍物的位置。两帧之间多数点对应的物理物体没有变化，变化的是雷达自身位置。前端的工作是求一个最优刚体变换（旋转加平移），使上一帧点云经变换后与当前帧点云的对齐程度最高。

这一过程常用 ICP（Iterative Closest Point，迭代最近点）完成，名称中的三个词各对应一个环节：

- **Closest Point**：对上一帧的每个点，在当前帧中找到距离最近的点，视为同一物理位置。
- **Iterative**：这一“最近点”关系依赖当前的变换估计，因此需要反复迭代：先给出初始变换，计算最近点，再用结果更新估计，循环至收敛。
- **Rigid**：变换为刚体变换，只允许旋转与平移，不允许物体自身变形。

ICP 的输出是从帧 t-1 到帧 t 的相对位姿增量 ΔP。

### 3.2 视觉 SLAM 的前端匹配

视觉 SLAM 不做点云对齐，而是在图像中提取角点或斑点（统称特征点），再在两帧之间建立特征点对应关系。

典型流程：

1. 用 SIFT、ORB、SuperPoint 等算子从当前帧提取特征点，每个特征点附带描述子，即描述其邻域像素的向量。
2. 用上一帧的特征点描述子，在当前帧中检索最相似者（欧氏距离或汉明距离）。
3. 得到一批“帧 t-1 的点 A 对应帧 t 的点 B”的匹配对。
4. 用 RANSAC 剔除大概率错误的匹配（如飞过的鸟、反光物体），保留可靠对应。
5. 用 PnP（单目）或 SVD（双目）从可靠对应中解出相机相对位姿。

### 3.3 前端的偏差来源：噪声与异常数据

激光与视觉前端获取的数据本身都不干净：

**传感器噪声**：激光雷达每秒发射数百万束光，其中一部分因灰尘、烟雾、水面反射而失效，或未击中物体，或测距错误。视觉相机在暗处产生噪点，逆光条件下特征点提取质量下降。

**动态物体干扰**：SLAM 默认环境静态。行人经过时，其身上的点不应参与匹配。主流做法是把当前帧的全部匹配对输入 RANSAC，由算法将不符合多数约束的配对判为离群值并剔除。RANSAC 的作用可以概括为：**找到能解释大多数观测的模型，无法被该模型解释的少量配对视为错误。**

**匹配失败**：帧间变化过大时，例如机器人急转弯或视线被遮挡，ICP 与特征匹配可能失败。SLAM 系统通常设有跟踪丢失检测：连续若干帧匹配质量低于阈值，即切换到重定位模式，用当前帧在已建地图中检索自身位置。检索成功则恢复跟踪；检索失败说明设备可能已超出地图覆盖范围，需要人工介入或转入探索模式。

**子图（Submap）缓冲**：部分激光 SLAM（如 Cartographer）不只做“上一帧与当前帧”的对齐，而是把最近 N 帧拼成子图，再用当前帧与子图对齐。单次匹配的参考更充分，抗瞬时噪声能力更强，代价是内存占用与计算量上升。

## 四、漂移：SLAM 的核心矛盾

考虑一个情形：只有前端在运行，地图会变成什么样？

机器人在大房间内沿闭合回路行走，从位置 A 出发，绕行一圈后应回到 A。前端每一帧都基于上一帧计算相对位姿，误差随之累积。走完一圈，机器人认为自己在 A'，而 A' 与真实的 A 可能相差数米。

这就是 **漂移（Drift）**。前端只保证局部正确：每一帧与上一帧对齐，但这一正确性没有外部锚点约束。单步的微小误差经过数百至上千帧累积，会持续放大。

漂移的成因有几类：

- **传感器精度**：低精度激光雷达单次测距误差可达厘米级，数百次累积后达到数十厘米。
- **运动模型误差**：轮式里程计假设轮子不打滑，实际存在地面摩擦、轮子磨损等因素。
- **前端匹配残差**：即便 ICP 收敛，对齐也不是完美对齐，总会留下残差。
- **几何退化**：在长走廊、空旷大厅、隧道中可用约束点过少，前端解算的位姿不稳定。

漂移带来的后果是地图变形：墙壁倾斜、房间重叠、不同区域之间错位。严重时，机器人在地图中无法完成定位，跟踪彻底失效。

## 五、回环检测：把漂移整体拉回

前端无法消除漂移，需要一种全局机制，即回环检测。

### 5.1 回环检测的原理

回环检测要回答的问题很朴素：**机器人当前看到的场景，是否为此前到过的地方？**

若答案为是，则当前位置与此前那个位置是同一物理位置，而前端给出的两个位姿之间存在一段漂移量。将这段漂移量作为额外约束插入位姿图，重新优化，即可把累积误差纠正回来。

一个类比：闭上眼睛在房间内行走，每步记录转向角度与移动距离，这相当于前端的相对位姿。走过多圈之后，无法确知自己站在何处。此时睁开眼，看到自己正站在红色沙发旁，而这正是出发时的位置。此前累积的位置误差，随即被“沙发”这一锚点拉回。

睁眼的瞬间对应回环检测的触发，沙发则对应机器人再次遇到的场景。

### 5.2 回环检测的实现方式

主流方案有两条路线。

**视觉回环**：基于词袋（Bag of Words, BoW）。预先将图像特征点聚类为视觉词典，每个词代表一类特征。每张图像编码为词频向量，记录命中了词典中的哪些词、各自出现几次。判断当前帧是否见过，即在历史帧中检索向量最相似者。BoW 优势是检索快，缺点是有误检风险：两张差异明显的图像可能包含相同的视觉特征组合。误检后果严重，把两个不同地点判为同一处，会使地图偏差扩大。

为降低误检率，DBoW3、FAB-MAP 等系统增加了几何验证：BoW 给出候选匹配后，再用特征匹配或 ICP 检验两处图像或点云能否对齐，通过验证才认定为回环。

**激光回环**：原理相近，匹配对象由图像变为扫描帧或子图点云。对点云做完整 ICP 匹配计算量过大，主流做法是 scan context：把每帧激光扫描转换为定长描述子（通常为极坐标下的网格投影），再用描述子做快速检索。Scan Context 对激光雷达的旋转与部分平移具有不变性，同时支持几何验证。

### 5.3 回环的触发与处理流程

完整流程如下：

```
当前帧数据
    │
    ▼
提取描述子（图像 BoW / 激光 Scan Context）
    │
    ▼
在历史数据库里检索候选匹配
    │
    ├── 没找到 → 正常，继续前端
    │
    └── 找到候选 → 几何验证（ICP / 特征匹配）
                        │
                        ├── 没通过 → 放弃这个候选，继续找或跳过
                        │
                        └── 通过 → 计算当前帧 ↔ 历史帧的相对变换
                                    │
                                    ▼
                          把这个变换作为新的约束，插入位姿图
                                    │
                                    ▼
                          触发全局优化（GTSAM、g2o、Ceres）
                                    │
                                    ▼
                          所有历史位姿一起被调整，漂移被整体拉回
                                    │
                                    ▼
                          重建地图（用新位姿重投影所有观测）
```

全局优化的数学本质是最小二乘。位姿构成节点，节点之间以相对变换约束相连，约束来自前端帧间匹配与回环跨时间匹配。优化器求解一组使全部约束满足程度最高的位姿。回环约束是其中最强的一类，因为它把两个物理上相同、前端却算出不同位姿的位置绑定在一起，其余位姿随之重新排布。

触发策略上，多数系统不逐帧执行回环检测，计算开销过高。常见做法是按时间窗口（每隔 N 帧）、距离阈值（行进多少米）或场景变化（当前帧与上一帧差异较大）触发。具体阈值与场景、传感器能力、算力有关。

## 六、地图维护：并非简单的点云拼接

前端提供每帧的位置，传感器提供每帧的观测，地图维护要把这些片段组装成可用的地图。

### 6.1 三类地图表示

- **点阵图（Point Cloud Map）**：最直观的表示，把每帧激光点云按对应位姿变换到全局坐标系后叠加。精度高，点数量增长快，后期占用内存较大。
- **栅格地图（Occupancy Grid Map）**：把空间划分为小方格，每格标记占用、空闲或未知。适合路径规划，会丢失物体表面细节。2D 栅格是扫地机器人与导航系统的常用形式。
- **拓扑地图与度量地图结合**：拓扑图由节点与边构成，节点表示门、转角、房间中心等重要位置，边表示连通关系；度量图提供精确坐标。两者结合可保留几何精度，并支持“去哪里”层面的规划。

### 6.2 地图更新与清理

地图是逐帧增量更新的。前端完成对齐后，观测到的点与特征投影到全局地图，与已有地标关联：来自同一物理位置的观测进行融合（取平均或以高斯分布更新），新的观测则新增为地标。

传感器噪声会使点云累积后出现模糊区域。多数系统会周期性清理地图：按置信度剔除可信度低的点，用体素下采样（Voxel Downsampling）使密集区域的点分布均匀，并按最新全局位姿重新投影。这些处理对后续导航质量影响明显。

## 七、建图质量的决定因素

一种常见的看法是，选一台好激光雷达就能画出好地图。实际结果由多个因素共同决定。

### 7.1 传感器硬件：基础但非全部

高档激光雷达（Velodyne、Livox、RoboSense 等）在测距精度、角度分辨率、点云密度、抗干扰能力上更优，会影响前端匹配质量与点云密度。硬件只是原材料：同一台雷达在不同算法参数与不同环境适配下，出图质量可以相差多个量级。

### 7.2 算法设计与参数调校

SLAM 系统中可调参数较多：

- **ICP 迭代次数与收敛阈值**：迭代次数多则精度高、耗时长；阈值放宽则速度快、精度下降。
- **RANSAC 样本数与内点阈值**：参数过松会保留错误匹配，过紧则丢失有效匹配。
- **回环检测触发间隔与匹配阈值**：触发过于频繁浪费算力，过于稀疏会漏检；阈值过高易漏掉真实回环，过低易引入假回环。
- **子图大小**：子图过小则参考不足、鲁棒性差，过大则内存与计算压力上升。

这些参数不存在通用最优值，需要针对传感器与使用场景调校。长走廊中激光雷达的旋转自由度观测充分、平移自由度观测薄弱，空旷大厅中则相反。合理的参数能让系统在不同环境下发挥硬件性能。

### 7.3 运动估计精度

SLAM 设有先验模块，融合 IMU、轮式里程计、视觉里程计等信息，给出比纯前端更稳定的运动估计。可靠的运动先验为前端提供较好的初始位姿，减少 ICP 的迭代负担；偏差较大的先验会把前端带偏，甚至引发误匹配。IMU 零偏与噪声参数标定、轮式里程计的轮径与轴距标定，这些基础工作的完成质量对建图结果影响很大。

### 7.4 特征匹配策略

视觉 SLAM 的特征提取与匹配策略决定系统对环境变化的适应能力。强光条件下 ORB 比 SIFT 更稳定；夜间室内，SuperPoint 这类基于深度学习的特征点表现更好。匹配使用汉明距离还是欧氏距离、阈值设为多少、是否启用 LK 光流跟踪，都会影响召回率与准确率。

### 7.5 环境适配

部分环境对 SLAM 天然不友好：**长走廊**中机器人只能观测到两侧墙面，前后方向缺少几何约束，前端会沿走廊方向漂移；**空旷大厅**可用特征稀少，匹配质量偏低；**玻璃幕墙与水面**会导致激光穿透或多次反射；**动态环境**（行人、车辆密集）会污染地图，甚至使前端匹配失败。对此类场景，系统需要针对性处理，例如在走廊中提高轮式里程计权重，在动态环境中用语义分割滤除移动物体，在激光穿透区域以视觉补充。

### 7.6 一个对比

上述因素叠加，会出现这样的情况：两台同型号 AGV、同型号激光雷达，在同一工厂内运行，一台地图干净、无明显漂移，另一台地图重叠歪斜。差异可能仅在于：

- 一台完成了 IMU 精细标定，另一台未做
- 一台的 ICP 收敛阈值更严格
- 一台的回环检测触发更及时
- 一台在动态区域增加了语义过滤

建图质量不由单一因素决定，而是传感器、算法、参数、标定与环境适配共同作用的结果。

---

SLAM 目前已是较为成熟的领域，开源算法、商用方案与应用场景都比较丰富。随着新型激光雷达与应用场景出现，系统仍需不断适配。这一领域的特点也在于此：它不只是数学问题，还包含大量工程权衡，需要在参数、阈值与标定中逐步消解同时定位与建图之间的矛盾。
