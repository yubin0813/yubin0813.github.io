> 初次读 URDF 的人几乎都会犯同一个错：看到 X、Y、Z 就下意识认为它们指向同一个方向。这个误解不纠正，后面的每一步变换推导都会在脑子里打架。

## 一、URDF 不只是模型文件

URDF（Unified Robot Description Format）字面意思是"统一机器人描述格式"，但"模型文件"这个说法只说对了一半。一个完整的 URDF 至少做两件事：

- 给每个 **link** 画出几何形状（外观、碰撞、惯性）；
- 用 **joint** 把 link 串起来，同时声明两者之间的相对关系。

第二种角色对做运动控制的人更关键——URDF 本质上是一棵以 `link` 为节点、`joint` 为边的树。根节点通常是一个空的虚拟 link（比如 `base_footprint`），整条路径从根一路走到末端执行器。这条链上每一个 joint 的原点和轴，决定了整条链的运动学。

下面用一个极简的两关节机械臂做例子，贯穿全文的所有代码和推导。

```xml
<robot name="simple_arm">
  <link name="base_link"/>
  <link name="link1"/>
  <link name="link5"/>

  <!-- joint1：连接 base_link 和 link1 -->
  <joint name="joint1" type="revolute">
    <parent link="base_link"/>
    <child  link="link1"/>
    <origin xyz="0.0 0.0 0.2" rpy="0.0 0.0 1.5708"/>
    <axis xyz="0.0 0.0 1.0"/>
  </joint>

  <!-- joint5：连接 base_link 和 link5 -->
  <joint name="joint5" type="fixed">
    <parent link="base_link"/>
    <child  link="link5"/>
    <origin xyz="0.1 0.0 0.3" rpy="0.0 0.7854 0.0"/>
    <axis xyz="0.0 1.0 0.0"/>
  </joint>
</robot>
```

两个 joint 都挂在同一个父 link 上，下文用它们演示坐标系之间的相对关系。

## 二、用 Python 读 URDF：find vs findall

URDF 是标准 XML，Python 自带 `xml.etree.ElementTree` 就能解析。典型的遍历方式如下：

```python
import xml.etree.ElementTree as ET

tree = ET.parse("simple_arm.urdf")
root = tree.getroot()

# 取出所有 joint 节点
for joint in root.findall("joint"):
    name = joint.get("name")

    # 每个 joint 下的子节点都是唯一的
    parent_name = joint.find("parent").get("link")
    child_name  = joint.find("child").get("link")
    origin      = joint.find("origin")
    axis        = joint.find("axis")

    xyz = [float(v) for v in origin.get("xyz").split()]   # "0.0 0.0 0.2" → [0.0, 0.0, 0.2]
    rpy = [float(v) for v in origin.get("rpy").split()]
    a   = [float(v) for v in axis.get("xyz").split()]

    print(f"{name}: parent={parent_name} child={child_name}")
    print(f"  origin xyz={xyz} rpy={rpy}")
    print(f"  axis={a}")
```

这里有两个容易写错的地方，记下来能省下不少调试时间：

**`find()` vs `findall()`**：

- `find("joint")` 只返回**第一个**匹配的子节点；
- `findall("joint")` 返回**全部**匹配节点的列表。

单个 joint 内部，`origin`、`axis`、`parent`、`child` 各只有一个，所以用 `find()`；但整个文档里有多个 `joint`，必须用 `findall()`。用错的后果很隐蔽——`find()` 遍历全部 joint 时只拿到第一个，结果少算了一堆却不报错。

**字符串转数组**：URDF 里的向量都是空格分隔的字符串（如 `"0.1 0.2 0.3"`），需要 `.split()` 拆开再逐个 `float()`。ROS 没有现成的解析函数在标准库里，这一步必须自己做。

## 三、三个关键参数的语义

`origin` 节点有两个属性，`axis` 节点有一个属性——加起来正好三个，分别回答三个不同的问题：

| 参数 | 所在节点 | 回答的问题                       | 类型     |
| ---- | -------- | -------------------------------- | -------- |
| xyz  | origin   | **装在哪里**               | 静态安装 |
| rpy  | origin   | **装的时候朝向哪里**       | 静态安装 |
| axis | axis     | **装好之后沿哪个方向运动** | 动态运动 |

把三者分开看，读 URDF 时就不会把安装偏移误当成运动方向。

### 3.1 xyz：装在哪里

`xyz="0.1 0.2 0.3"` 给出的是关节原点相对**父 link 坐标系**的位置偏移，单位是米。也就是说：

- 原点的位置 = 父 link 的原点 + xyz 向量；
- x、y、z 三个分量的参考系是**父 link** 的那套坐标轴，不是子 link 的。

看例子里的 `joint1`：`xyz="0.0 0.0 0.2"` 表示 joint1 的原点在 `base_link` 坐标系的 Z 轴上 0.2 米处。`joint5` 的 `xyz="0.1 0.0 0.3"` 则表示 joint5 的原点在 `base_link` 的 X=0.1、Z=0.3 的位置。两者都以同一套父坐标系为参照，所以可以直接比较谁在谁的哪个方向。

### 3.2 rpy：装的时候朝向哪里

`rpy="roll pitch yaw"` 三个角分别对应绕 X、Y、Z 轴的旋转。URDF 文档明确规定：这是**绕固定父坐标轴**的 extrinsic 旋转，执行顺序为 **X（Roll）→ Y（Pitch）→ Z（Yaw）**。

转换成旋转矩阵时要注意：矩阵乘法顺序与应用顺序**相反**。先执行的旋转写在右边，后执行的写在左边：

```
R = Rz(yaw) · Ry(pitch) · Rx(roll)
```

三个基本旋转矩阵为：

```
Rx(θ) = [1    0      0   ]
        [0   cosθ  -sinθ ]
        [0   sinθ   cosθ ]

Ry(θ) = [ cosθ  0   sinθ ]
        [ 0     1    0   ]
        [-sinθ  0   cosθ ]

Rz(θ) = [cosθ  -sinθ  0  ]
        [sinθ   cosθ   0  ]
        [ 0      0     1  ]
```

例子里 `joint1` 的 `rpy="0.0 0.0 1.5708"`，即 yaw = π/2，roll 和 pitch 都是 0。代入上面的公式：

```
R₁ = Rz(π/2) · Ry(0) · Rx(0) = Rz(π/2) = [0  -1   0]
                                          [1   0   0]
                                          [0   0   1]
```

这正好是把 X 轴旋转到 Y 轴位置的标准旋转矩阵。

再看 `joint5`：`rpy="0.0 0.7854 0.0"`，即 pitch = π/4，代入得：

```
R₂ = Rz(0) · Ry(π/4) · Rx(0) = Ry(π/4) = [ 0.707  0  0.707]
                                           [ 0      1  0    ]
                                           [-0.707  0  0.707]
```

它的 Y 轴保持不变，X 轴转到了水平面内 45° 向下的位置。

### 3.3 axis：装好之后沿哪个方向运动

`axis` 只对可动关节（revolute / continuous / prismatic / planar）有意义。它声明关节**自身**的运动轴，单位向量，参考系是**子 link 安装好之后的那套坐标系**。

- 旋转关节（revolute / continuous）绕该轴旋转；
- 移动关节（prismatic）沿该轴平移。

固定关节（fixed）没有运动，axis 写不写都行，但 URDF 规范里建议保留以便阅读。

例子里 `joint1` 的 `axis="0 0 1"` 表示装好之后绕子 link 的 Z 轴转；`joint5` 是 fixed，axis 理论上可以省略，但例子里写了 `"0 1 0"` 只是为了展示字段位置。

### 3.4 一句话总结

> **xyz 是装在哪里，rpy 是装的时候朝向哪里，axis 是装好之后沿哪个方向动。**

前两者是静态安装信息，描述"这个 joint 相对父 link 摆成什么姿态"；后者是动态运动信息，描述"关节动起来时朝哪个方向"。

## 四、坐标系的陷阱：同名 ≠ 同向

这是本文想纠正的核心误解。

每个 link（以及连接它的 joint）都有一套自己的 XYZ 坐标系。虽然都叫 X、Y、Z，但在空间中的实际指向可以完全不同。`base_link` 的 X 轴朝东，`link1` 的 X 轴可能已经转到了朝南；两者的原点位置也不一样。**讨论"某个方向"时必须先说明是哪个坐标系下的方向，否则同一句话可以有不同含义。**

以例子里的两个 joint 为例，它们各有各的坐标系：

- `joint1` 经过 yaw = π/2 的旋转，它的 X 轴在 `base_link` 坐标系下指向 +Y 方向；
- `joint5` 经过 pitch = π/4 的旋转，它的 Z 轴在 `base_link` 坐标系下指向 (-sinπ/4, 0, cosπ/4)，即向前下方 45°。

两套坐标系的同名轴既不同向，原点也不同。如果只说"沿 X 轴平移 0.1 米"，在 joint1 坐标系下是向 +Y 走 0.1 米，在 joint5 坐标系下又是另一个方向——必须先指明是哪一套。

进一步，坐标系之间的完整关系由两部分组成：

- **旋转矩阵 R**：描述方向关系，即"目标坐标系的三根轴在参考坐标系下指向哪里"；
- **平移向量 t**：描述原点位置关系，即"目标坐标系的原点在参考坐标系下的位置"。

二者合起来才是完整的刚体变换。只给 R 不知道原点在哪里，只给 t 不知道坐标轴指向哪里，单独一个都无法确定另一个。

## 五、推导两坐标系间的相对旋转

现在用一个具体场景做推导。设 `base_link` 为共同参考系，`R₁` 是 `joint1` 相对 `base_link` 的旋转（上一节已算出 `R₁ = Rz(π/2)`），`R₂` 是 `joint5` 相对 `base_link` 的旋转（`R₂ = Ry(π/4)`）。我们要找 `joint1` 相对 `joint5` 的旋转，记作 ⁵R₁——上标是目标坐标系，下标是源坐标系。

### 5.1 分三步走通

任意一个在 `joint1` 坐标系下表示的向量 `v¹`，要转换到 `joint5` 坐标系下，可以先把它用 `R₁` 转到 `base_link`（共同参考系），再用 `R₂⁻¹` 从共同参考系转回 `joint5`：

```
v⁵ = R₂⁻¹ · R₁ · v¹
```

对比坐标变换的标准形式 `v⁵ = ⁵R₁ · v¹`，立即得到：

```
⁵R₁ = R₂⁻¹ · R₁
```

### 5.2 为什么顺序不能反

直接代入数字算一下就能体会。先算正确结果：

```
R₂ = Ry(π/4) = [ 0.707   0   0.707 ]
               [ 0       1   0     ]
               [-0.707   0   0.707 ]

R₂⁻¹ = R₂ᵀ（旋转矩阵是正交矩阵，逆等于转置）
     = [ 0.707   0  -0.707 ]
       [ 0       1   0     ]
       [ 0.707   0   0.707 ]

R₁ = Rz(π/2) = [ 0  -1  0 ]
               [ 1   0  0 ]
               [ 0   0  1 ]

⁵R₁ = R₂ᵀ · R₁
    = [ 0.707   0  -0.707 ] [ 0  -1  0 ]
      [ 0       1   0     ] [ 1   0  0 ]
      [ 0.707   0   0.707 ] [ 0   0  1 ]

    = [ -0.707  -0.707   0 ]
      [  1       0       0 ]
      [  0.707  -0.707   1 ]   ← 这个结果才是对的
```

如果顺序反过来算 `R₁ · R₂ᵀ`，得到的是另一个完全不同的矩阵——它看着也"像个旋转矩阵"（正交矩阵），但实际表示的是从 `joint5` 到 `joint1` 的方向，而不是我们想要的从 `joint1` 到 `joint5`。顺序反了没有报错，必须靠推导逻辑确认。

### 5.3 R⁻¹ = Rᵀ 的意义

旋转矩阵是正交矩阵，满足 `RᵀR = I`，因此 `R⁻¹ = Rᵀ`。这不只是公式上的简化，实际数值计算中避免了通用矩阵求逆带来的误差累积——直接转置比 Gauss 消元快、准、稳。

完整公式链：

```
⁵R₁ = R₂⁻¹ · R₁ = R₂ᵀ · R₁
```

记忆口诀：**先把源坐标系转到共同参考系（R₁），再从共同参考系转到目标坐标系（R₂ 的逆即转置），两者相乘就是目标坐标系下的变换。** 乘法顺序遵循"离源近的先乘"。

## 六、总结

把最初的那段 XML 重新看一遍，现在每一行都应该有了明确的含义：

```xml
<origin xyz="0.0 0.0 0.2" rpy="0.0 0.0 1.5708"/>
<!--  装在 base_link 的 (0, 0, 0.2) 处，绕 Z 轴转了 90°  -->

<axis xyz="0.0 0.0 1.0"/>
<!--  装好之后，绕子 link 自身的 Z 轴旋转  -->
```

几条反复出现、值得专门记下来的收获：

1. **xyz、rpy、axis 分别回答三个不同问题**：装在哪里、装的时候朝向哪里、装好之后沿哪个方向动。前两者是静态安装信息，后者是动态运动信息。
2. **`find()` 与 `findall()` 的区别决定遍历方式**：单个 joint 内部子节点用 `find()`，跨 joint 遍历用 `findall()`。用错不会报错，只会静默少算。
3. **同名不代表同向**：每个 link 有自己的 XYZ，名字一样但空间指向完全可以不同。讨论方向必须先声明坐标系。
4. **R 与 t 各管一件事**：R 只管方向，t 只管原点位置。合起来才是完整变换。
5. **相对旋转的乘法顺序不能靠感觉**：⁵R₁ = R₂ᵀR₁ 遵循"先统一到共同参考系、再转到目标系"的逻辑，顺序反了结果看着"正常"但含义完全不同。
6. **R⁻¹ = Rᵀ 把求逆降为转置**：旋转矩阵是正交矩阵，逆等于转置。实际计算中转置更快更稳。
